## How the pieces fit together

**The core idea** is two parallel channels working together:

1. **WebSocket** — for real-time in-app notifications while the user has your tab open
2. **Web Push API + Service Worker** — for OS-level system notifications, even when the tab is closed or the browser is minimized

---

## Backend: Java / Spring Boot

**WebSocket with STOMP:**
```java
@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {
    @Override
    public void configureMessageBroker(MessageBrokerRegistry config) {
        config.enableSimpleBroker("/topic", "/queue");
        config.setApplicationDestinationPrefixes("/app");
    }
    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws").setAllowedOrigins("*").withSockJS();
    }
}
```

**Sending a notification from any service:**
```java
@Service
public class NotificationService {
    @Autowired private SimpMessagingTemplate messagingTemplate;

    public void sendToUser(String userId, NotificationDTO notif) {
        // In-app via WebSocket
        messagingTemplate.convertAndSendToUser(userId, "/queue/notifications", notif);
        
        // OS push via Web Push API
        pushNotificationService.sendPush(userId, notif);
    }
}
```

**Web Push (system notifications)** — add the `java-webpush` library:
```java
// Generate VAPID keys once, store them
PushService pushService = new PushService(publicKey, privateKey, "mailto:you@app.com");

Notification notification = new Notification(
    subscription,  // stored per-user from frontend
    new JSONObject().put("title", "New message").put("body", "You have 3 unread items")
);
pushService.send(notification);
```

## Frontend: React

**WebSocket hook:**
```javascript
// useNotifications.js
export function useNotifications(userId) {
    const [notifications, setNotifications] = useState([]);

    useEffect(() => {
        const client = new Client({
            webSocketFactory: () => new SockJS('/ws'),
            onConnect: () => {
                client.subscribe(`/user/queue/notifications`, (msg) => {
                    const notif = JSON.parse(msg.body);
                    setNotifications(prev => [notif, ...prev]);
                    showSystemNotification(notif); // OS popup
                });
            }
        });
        client.activate();
        return () => client.deactivate();
    }, [userId]);

    return notifications;
}
```

**OS system notification (the key part):**
```javascript
async function showSystemNotification({ title, body, icon }) {
    // Request permission once (browser prompts user)
    if (Notification.permission === 'default') {
        await Notification.requestPermission();
    }
    if (Notification.permission === 'granted') {
        // This triggers the native OS notification tray
        new Notification(title, { body, icon, badge: '/badge.png' });
    }
}
```

**Service Worker** (for push when tab is closed — `sw.js`):
```javascript
self.addEventListener('push', (event) => {
    const data = event.data.json();
    self.registration.showNotification(data.title, {
        body: data.body,
        icon: '/icon.png',
        badge: '/badge.png',
        data: { url: data.url }
    });
});

self.addEventListener('notificationclick', (event) => {
    event.notification.close();
    clients.openWindow(event.notification.data.url);
});
```

**Register service worker + subscribe to push in React:**
```javascript
useEffect(() => {
    navigator.serviceWorker.register('/sw.js').then(async (reg) => {
        const subscription = await reg.pushManager.subscribe({
            userVisibleOnly: true,
            applicationServerKey: YOUR_VAPID_PUBLIC_KEY
        });

}, []);
```

## Is real-time possible? Yes, completely.

| Scenario | Mechanism | Latency |
|---|---|---|
| Tab open, user active | WebSocket (STOMP) | ~10–50ms |
| Tab open, user idle | WebSocket | ~10–50ms |
| Tab in background | Web Push → service worker | 1–3s |
| Browser closed | Web Push → service worker → OS tray | 1–5s |
| App not installed | Web Push still works in modern browsers | 1–5s |

**A few things to keep in mind:**

- The `Notification.requestPermission()` call must happen in response to a user gesture (button click) — browsers block auto-prompts on page load.
- For multi-tab scenarios, WebSocket connections are per-tab; use Redis Pub/Sub or a message broker on the backend so any server instance can reach any user.
- iOS Safari support for Web Push only arrived in Safari 16.4 (2023) — it works but needs an installed PWA on iOS.
- Store push subscriptions in your DB per user so the backend can always reach them even when offline.

The `java-webpush` library on Maven Central handles all the VAPID signing complexity for you — that's the hardest manual part otherwise.
